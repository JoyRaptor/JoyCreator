## 2. Accurate waveform display  ⚠️ ASKED "did we already do this?" — ANSWER: NO (not on the timeline bar).
CODE-VERIFIED ground truth:
- The timeline AUDIO-BAR waveform (what JoyRaptor edits by) is generated by
  `FaditorEditorActivity.generateWaveform(uri, track, 800)` — a FIXED 800 samples for the WHOLE clip
  (so a 60s clip ≈ 13 samples/sec) and drawn by `EditorTimelineView.drawAudioTrack` (~line 3407) with
  naive POINT-SAMPLING + linear interp — one interpolated sample per 3dp bar. Zoomed out (bars < samples)
  it skips the peaks between points → the "too averaged-out, can't line up words / see quiet onsets" look.
- The HD data ALREADY EXISTS elsewhere: `WaveformExtractor` = 60 buckets/sec + FFT, disk-cached
  (CACHE_VERSION 3) — but only the VISUALIZER uses it, NOT the timeline audio bar.
- So the roadmap's "W1 waveforms shipped by opencode r2" = basic waveforms RENDER (display exists), NOT
  the fidelity fix. The fidelity fix is specced in `FEEDBACK_20260703_timeline_fidelity.md`:
  - **W1** (SMALL, render-only): per-pixel-column MIN/MAX peak-preserving envelope + perceptual log/sqrt
    scaling (~-60dB floor) + optional soft RMS body. Feed the bar the high-res extractor data.
  - **W2** (MEDIUM): HD zoom tier (200–400 buckets/sec for the visible span) → letter-level onsets.
  Status: **OPEN, never built on the timeline bar.** W1 is genuinely small because the data mostly exists.
