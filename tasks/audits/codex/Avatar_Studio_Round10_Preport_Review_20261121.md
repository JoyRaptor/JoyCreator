# Avatar Studio Round 10 code review

**November 21, 2026 · Joy Creator Studio · AVA-1**

I would keep **Set up → Fit → Motion → Perform** as the phone workflow. Before porting every rig control, I would prove one complete loop with Topps: create a character, fix a drawing or pin, record a take, switch away and reopen it, send it to Studio, then export the same performance. The prototype currently loses work along that path and can export different colours than it previews.

## Performance and export

- **Save work stalls the editing thread.** Five synchronous serializations of the 89-image bundled Joybot rig took **181–400 ms** each on this Windows PC. This measures PNG encoding and document serialization, before IndexedDB, shelf previews or a phone are involved. Each autosave re-encodes every referenced image, including after a pin-only edit. Save pixel assets once per revision, commit only changed rig and take data, and create shelf thumbnails off the interaction path. [Image serialization](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-model.js#L129-L136) · [Shelf thumbnail](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-shelf.js#L16-L28)
- **Set up and Fit can solve and redraw an unchanged character every refresh.** The frame loop re-evaluates the solver, draws the scene and redraws editor overlays even with no camera motion or live input. In a disposable idle fixture, Topps made 60 vertex, UV and index buffer uploads per draw and Joybot made 105. Keep UV and index buffers resident where topology is stable. Render static stages on invalidation. Keep animations active only while the selected preview needs them. Measure frame times, memory and touch latency on the test Note 9 with Topps, Joybot and a dense PSD. [Frame loop](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-app.js#L238-L276) · [Buffer uploads](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-gl.js#L80-L89)
- **Sprite sheets need an explicit export range and packaging.** Bake runs two full solver passes synchronously and supports at most 96 frames at a minimum 4 fps, so a long take can only produce the first 24 seconds. The 256 px cells and two separate saves suit pilot interchange. Give artists a range, resolution and estimated output before starting, then let the job report progress, cancel and deliver the PNG and settings together. Keep one simulation clock for preview, scrub and export, including stateful walk, wind and stance easing. [Bake implementation](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-intake.js#L501-L527)
- **Large layered files still need a memory budget.** The bundled Topps rig proves a specific layered character can open. Parallel layer decoding and CPU/GPU image copies need a bounded queue and cancellation with a production-sized PSD. Keep the original art and exploit smaller interactive textures with the same source-space coordinates. Report unsupported blend and clipping features before committing the import. [PSD decode](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-psd.js#L140-L185) · [PSD import review](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-intake.js#L115-L131)

## Phone workflow

Keep the four stages, with the room remembering the selected part and drawing as the artist moves between them. The stage names describe why someone is there. Give the editing screen a persistent part and angle label, and keep **Undo**, the current tool and the escape from an active tool within thumb reach. A pin edit should have a zoomed view or a nudge control. Use Topps’s Left Quarter eye and Joybot’s hand angle as the artist-facing checks.

- **Frequent controls are small on the phone layout.** At 360 × 640, the main menu and its Open, Save and Send buttons had 34 × 34 px hit areas, and stage tabs were 30 px tall. In 640 × 360 landscape, the take scrub area narrowed to 97 px. Keep the compact icon artwork and expand the touch targets. Provide a full-width scrub view or one-finger controls for precise take corrections. [Phone layout and button sizes](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/index.html#L55) · [Stage tabs](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/index.html#L127)
- **The menu sheet leaves focus on the background.** Opening it left focus outside the sheet. Escape left it open in both tested orientations. The sheet is a generic element and the open and close functions change visibility only. Use a modal sheet with a named title, initial focus, Back and Escape handling and focus restoration. Run TalkBack and switch or keyboard navigation against the native controls. [Sheet behavior](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-app.js#L511-L527)

Give **Save state**, **source activity**, and **recording state** separate visible feedback. The artist should know which character owns the take, whether the current move edits the rig or performs it, and when a permission or save needs attention. An imported voice file currently drives mouth controls. A take stores those samples without the audio file or its timeline offset. If Studio should carry the voice, copy it into the project and map its timing explicitly. [Voice file](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-inputs.js#L58-L72) · [Take channels](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-inputs.js#L118-L135)

## Android and Studio acceptance

- **The pilot needs an importer and migration path.** The web writer emits `.character.json` with `joycreator.character/1`, a node tree, images and an optional take. Native bundle detection expects `joyAvatar` with an ID and name, and loads separate rig and sheet records. The Android take reader interpolates floats and steps only the viseme class. Web trigger edges, explicit hand release, custom pins and stance channels need mappings and fixtures of their own. [Pilot writer](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/tools/avatarlab/al-intake.js#L46-L49) · [Native bundle detection](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/app/src/main/java/com/fadcam/joyfolder/studio/AvatarBundleFile.java#L116-L135) · [Native track sampling](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/app/src/main/java/com/fadcam/ui/faditor/avatar/AvatarParamTrack.java#L77-L116)
- **The existing Studio left-trim path can restart a performance.** Source trace. The left trim updates the overlay start and shifts transform keys. The renderer then samples the unchanged take from the new clip start. On a clip whose visible start is moved 1 second to the right, the first visible frame asks for take time 0 instead of 1 second. The split path already carries the recorded motion forward. Use a reversible source-window offset for trim, and prove Move, Trim, Split, Undo, restore and export with a take that visibly changes in the cut section. [Timeline trim](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/app/src/main/java/com/fadcam/ui/faditor/layers/LayerGestureController.java#L2466) · [Sprite range and local time](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/app/src/main/java/com/fadcam/ui/faditor/sprite/SpriteOverlayItem.java#L306-L361) · [Video export](https://github.com/JoyRaptor/JoyCreator/blob/13c517c93/app/src/main/java/com/fadcam/ui/faditor/export/CompositeExportOverlay.java#L1174-L1179)

1. **Settle one native character and take contract.** Share the same core and document format across the standalone Android app and the Joy Creator room. Version rig data and asset references, preserve stable node and channel IDs, and provide migration for existing native avatars. Treat image, audio and timeline-local take references as part of the saved project.
2. **Prove an editable layer in Studio.** Bring one rig and take into a test project. Move or trim the clip and save, restore and reopen the project. Keep the user's take and a live hand override. Validate the same samples and rendered pose at the same clip time in preview and video export.
3. **Prove resilience on the test Note 9.** Create and reopen a rig with multiple passes on different characters, background during a save, force-stop after a completed pass, switch characters repeatedly, and deny or delay permission. Verify recovery, matching output and one-handed use in portrait, landscape and increased system text. Follow with realistic large-art and long-take measurements.
