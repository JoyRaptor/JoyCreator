### SAVE-ROTATE · A recovered Studio project can lose its last readable backup during the next save

[ProjectStorage.java](https://github.com/JoyRaptor/JoyCreator/blob/7c3e1f04d4744b502d8829f2caae9e7cec3a0462/app/src/main/java/com/fadcam/ui/faditor/project/ProjectStorage.java#L525) lines 525–575 falls back to a readable project.json.bak when the main file is corrupt. On the next save, lines 350–395 sync the temporary JSON, delete that readable backup, and rotate the corrupt main into its place. A process stop between rotation and promotion leaves a valid .tmp and corrupt .bak; ordinary load examines main and .bak, not .tmp. A failed promotion also attempts to restore the corrupt file and deletes the good temporary. Other preserved copies may exist. Keep the verified recovery generation until a newer generation is published and readable. On startup validate main, recovery and orphaned staging candidates and preserve ambiguous files. Gate with disposable files: corrupt main plus good backup, open, edit, stop after each operation, and reopen. Verify every cut offers at least one known-good generation and never silently rolls forward partial JSON.

**Host fault checkpoint.** A disposable Java harness ran the production temp-write, sync and rotation statements, then stopped before promotion. The directory contained no project.json, an unreadable project.json.bak and a valid revision 2 in project.json.tmp. The ordinary fallback at lines 525–589 does not select that temporary. This checks file state at the interruption boundary; an Android cold-launch test is still due.

### AUD-BAKE · Cleaning a short extract late in a file pays for the entire silent lead-in

[BakedAudioCache.java](https://github.com/JoyRaptor/JoyCreator/blob/7c3e1f04d4744b502d8829f2caae9e7cec3a0462/app/src/main/java/com/fadcam/ui/faditor/audio/BakedAudioCache.java#L438) lines 438–477 trims the requested source span and adds startMs worth of silence before AAC encoding. This preserves current clip source coordinates. A 10-second dialogue clip beginning 60 minutes into a recording produces 3,610 seconds of nominal output: 361× the audio duration that needs processing, including 3,600 seconds of silence to encode and index. FFmpeg applies denoise before the delay; the additional cost is in encoding, storage and consumers traversing the long output. File-size and runtime savings need measurement. Store the baked source-time origin alongside a local zero-based segment and translate all preview, waveform, cuts, export and undo seeks. Read older padded bakes without migration until re-render. Gate with the same middle/end-of-file trim, A/V alignment, filter latency, split/undo and a missing-cache rebuild. Prefer a lossless working intermediate for repeated production editing after measuring space.

**Measured host encode.** On the identical 9.43 s mono fixture using FFmpeg 7.0.2 and the production Denoise/AAC settings, three zero-prefix runs took 196, 258 and 253 ms (median 253 ms, 236,384 bytes). Three ten-minute-prefix runs took 1,487, 1,532 and 1,505 ms (median 1,505 ms, 463,063 bytes). A separate completed one-hour-prefix run took 15331 ms (1,596,268 bytes), 60.6× the baseline median wall time. This isolates the prefix after trimming on a desktop. A segment-local Android implementation still needs edit-clock parity tests.

### AUD-RAIN · The Voice preset passes the hum check but missed a speech-in-broadband-noise test

Host experiment at the audited commit. The same production FxChain.createVoiceChain that passed the 9/9 hum test processed 9.43 s of synthetic spoken English with deterministic rain-like noise added at +5 dB power SNR. The input scored +4.91 dB scale-invariant signal-to-distortion ratio against dry speech. After aligning the limiter’s 10-sample delay, the processed output scored +1.24 dB against dry speech and +2.63 dB against the same clean speech passed through the Voice preset. The second reference accounts for the intended tone change. All 452,616 samples returned and the mixture had no clipped samples. This is one synthetic fixture, no listening verdict or CapCut score.

Reproduction: Windows System.Speech default English voice, PCM16/48 kHz mono, spoken text “Soft rain falls across the studio window. Listen for the quiet end of each sentence. Six small brushes sit beside the lamp.” Scale speech peak to 14,000. LCG seed 20261119, recurrence (1664525·s+1013904223) mod 2³². For each sample draw two uniforms. Set z=2u₁−1, low += .14(z−low), drop=.992·drop + (.8 if u₂<.0008 else 0), noise=(z−low)(.28+drop)+low, initial states zero. Scale the noise to +5 dB speech/noise, sum, round to PCM16. Compare zero-mean SI-SDR using output from VoiceChainTest.drive, with the 10-sample limiter delay removed for the dry reference.

Priority: audition a speech-specific denoiser on a dialogue bus with an intensity control, an aligned bypass, and cached processed dialogue keyed by source revision, time range, sample format, model and settings. Avoid applying dialogue suppression to music or six surround channels by default. Test dry speech, real rain during speech and pauses, sibilants, breaths, transients and a stereo room recording. Loudness-match the same input and CapCut reference for a blind comparison with the owner.
