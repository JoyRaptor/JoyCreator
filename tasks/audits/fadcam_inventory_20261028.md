# FadCam inventory: what is still FadCam's, and what to do with each part

Job: [FREE-1](../jobs/FREE-1_fadcam_inventory.md)  ·  Date: 2026-10-28  ·  Read-only audit, nothing built, no phone, no source edited.
Code read at `origin/joy-creator` `d28d73ba3`. Upstream FadCam: github.com/anonfaded/FadCam. **Not legal advice.**

## How "FadCam-derived" was measured (and what it cannot tell you)

- The first commit in this repo (`5abcbbe52`, 2026-06-05, author "Faded") is a snapshot of upstream FadCam: 1,773 files, 366 of them Java under `app/src/main/java`.
  The next commit (`78c82cd36`, 2026-07-01, JoyRaptor, "Joy Creator baseline") says in its message it is "All Faditor work to date on top of upstream FadCam 5abcbbe".
  Every later commit (2,810 of them) is JoyRaptor, Claude or opencode. So **a file in that first snapshot is FadCam's; a file added after it is Joy Creator's.**
- For each file now present I counted how many of its snapshot lines are still unchanged (snapshot lines minus lines deleted since, via `git diff --numstat -M`, renames followed, capped at the file's current length).
  **"FadCam lines" below means lines still present from the snapshot.** It is a diff measure, not a copyright finding: a line reworded slightly counts as rewritten, and a file written fresh in FadCam's style counts as Joy Creator's.
- Whole-snapshot limits: the snapshot has no history before 6-05 (upstream is ~1,845 commits ahead of it per memory), so I cannot see who wrote what upstream. Everything dated by its first commit is "present at the fork".
- Numbers are lines of Java/Kotlin unless a row says otherwise. Counts are estimates to the nearest few hundred; the direction of every verdict does not depend on them.

## Summary (5 bullets)

- **About 160,500 lines of FadCam code are still in the app: 37% of the app module's 436,800 Java lines, and 30% of all Joy Creator source (540,900 lines of Java/Kotlin across app, JoyBrush, JoyBrush-Android and the Studio kit).** JoyBrush, VisLab, the lobby, Library v2, Recently deleted, the Settings hub, About and the Joy folder are 100% new. Nothing in `joybrush`, `joybrush-android` or `studiokit` is FadCam's (they only borrow the `com.fadcam.*` package name).
- **The Studio is already almost clean.** `ui/faditor` is 246,000 lines in 474 files; only about 9,500 lines (3.8%) survive from the snapshot, spread over 26 files (the editor activity keeps ~1,500 of its 49,600 lines, the timeline view ~1,700). Its seam to FadCam-origin code is **10 classes** (the logger `FLog` in 90 files, `SharedPreferencesManager` in 15, `Constants`, two small data classes, one remuxer). Cutting that seam is days of work, not weeks.
- **The recorder side is almost entirely FadCam's, unchanged: 95-99% of every recorder area.** The big ones: Home screen 12,900 lines, the recording service 7,000, the screen-recorder with annotation 23,400, classic Records and players 28,800, Remote/streaming 10,300, forensics + motion 10,000. This is where "rebuild clean" work is. Library v2, Recently deleted and the Settings hub are skins over FadCam data code (`TrashManager` 1,200 lines, `VideoIndexRepository`/`FastFileScanner`, the classic settings fragments), so they do not yet free the tie.
- **Three things should leave before any public build, and one is worse than the plan says.** The app still contains FadCam's developer's own cloud: a Supabase project URL and publishable key, `id.fadseclab.com`, `live.fadseclab.com`, plus links to their Ko-fi, Patreon, Discord and GitHub, and a fetch from the upstream GitHub raw URL (push notifications). Cloud sign-in would send users' data to that backend. The "View source" link in About points to `github.com/fadsec-lab/`, not to Joy Creator's source (a GPL duty for our build).
- **About 30 classes (~4,500 lines) have no live caller**, the 11 already named by S10 plus ~17 more found now (full list below), including `AvatarToggleView` (now fully replaced by the Joybot switch). Several are half-built seek/playback pieces that fit the "save the orphans" rule: look before deleting.

## Licence note (not legal advice; ask a lawyer before relying on it)

- FadCam is GPL-3 (`LICENSE` is the GPL-3 text). While any FadCam-derived code ships, **the whole combined app is distributed under GPL-3**, source must be offered, and the copyright notices stay. This does not go away by rewriting a file "in the same project": a rewrite counts as clean only if it was written without copying the old file (ideas and behaviour are free; code and structure that follow the old file are copies). A clean-room route: one person writes a behaviour spec from the old screen, a different person (or session that has not read the old file) builds from that spec.
- **Today about 30% of source lines (37% of the app module) are still FadCam's, and the rest of FadCam's design (layouts, 77% of layout XML, translations) is too.** Both channels (Play and side-load) are GPL-3 builds. Removing cloud, disguise icons etc. changes what ships, not the licence.
- JoyBrush, VisLab, lobby/Library/Settings hub/Trash v2/About and Studio's 96% rewrite are Joy Creator's own work and can carry a different licence only if they could be separated from the GPL code. They are linked into one app today, so they ship under GPL-3 anyway. Cutting the tie (all of A1-A18 gone or clean-room rebuilt) is what would let the owner pick the licence for his own code. The Studio is the nearest to that.
- **Attribution that must stay while FadCam code ships:**
