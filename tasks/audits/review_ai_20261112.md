# Review of Joybot and the AI tools, 2026-11-12

Read-only review by Claude Sonnet 5.5 of `app/src/main/java/com/fadcam/ui/faditor/ai/**` and the AI hooks in
`FaditorEditorActivity.java`, on branch `claude/review-ai-20261112`. Nothing was built or run on a phone. Every
finding was traced in the source. **CONFIRMED** = traced end to end. **LIKELY** = strong, but one link
(usually a runtime fact) was not verified. Line numbers are as of this branch and will drift. Paths are relative
to `app/src/main/java/com/fadcam/ui/faditor/` unless they start with `app/`.

Top of the list, in plain words: (1) any app on the phone can rewrite a project through an unlocked door;
(2) "move clip to the end" puts the clip one place short; (3) the older AI "delete clip" and "set speed" leave
titles, music and transitions where they were while the footage moves; (4) AI b-roll suggestions use the wrong
clock and land in the wrong place; (5) a slow AI step can replace the person's newer edits in the open editor;
(6) the computer bridge listens on every network interface and its pairing code outlives each switch-on.

## Checked and sound

- **EditScript apply.** Scripts with structural ops are simulated on a deep copy, then replayed live; the begin/end
  structural bracket is in a `finally`, so a failed op cannot leave it open (`EditScriptApplier.java:124-186`).
  `REORDER_CLIPS` refuses incomplete lists (no silent deletion) and rolls clips and transitions back if the rebuild
  throws. `REMOVE_SPAN` really cuts and re-homes pieces. Split and b-roll re-anchor riders. Every caller drops the
  working copy on failure, so a half-applied script is never saved.
- **Live editor rules.** `JoybotStorage` refuses to read a possibly older file while the editor owns the project,
  withdraws a main-thread post that never started so it cannot land late, and counts a write only when it really saved
  (`JoybotStorage.java:44-137`). `JoybotAgent.runTool` turns a refused save into an error rather than a success (`:911-913`).
- **Slow tools re-read first.** `generate_transcript` and `detect_silence` reload the project when the work finishes and
  refuse if the clip was removed, swapped or re-trimmed (`AIToolExecutor.java:535-560,623-650`).
- **Studio actions.** One load, one save, "not saved means not done", item locks checked first (`StudioActions.java:98-135`).
- **Undo.** One step per request: the first changing tool parks the "before" snapshot and later tools merge into it.
  `DirectRunner.undo` puts the step back if the write fails. `revertTo` refuses if the project changed since the job
  finished (fingerprint check, `JoybotAgent.java:1850-1858`). Live writes merge by request token in `adopt`. The editor
  drains parked steps into its own undo on resume.
- **Timeline clock in the AI.** Starts and lengths use `getVisualDurationMs` (the editor's uncompressed clock)
  consistently; the AI code does not mix in file time (`TimeMap` is export-side). `INSERT_BROLL_CUTAWAY`'s own
  validation is consistent with the editor clock; the fault in B3 is the input it is given.
- **Empty and sound-only projects.** `getClip(0)` uses are guarded (`AIToolExecutor.java:3069`,
  `ProjectFactsReader.java:99`); the narrative and b-roll tools search for a clip with a transcript instead of clip 0;
  `JoybotEyes.composed` handles total 0; `export_video` refuses a project with no clips in plain words.
- **Bridge basics.** Browser requests (any `Origin`) are refused; the code compare is constant-time; first paired IP
  only; lock-out after 8 wrong codes; 4 MB body cap, body read before refusing; service is `START_NOT_STICKY` and not
  exported; the tool list is Joybot's own (no raw file or shell tools); `add_media` only resolves files that
  `list_media` offers (`SourcesActions.resolve`); export is a confirmation card, never a silent start; a lock or delete
  waits for the phone (`JoybotAgent.java:514-516`).
- **Keys.** The API key goes only to the configured provider's own base URL (`AiRequest.java:95`, `JoybotAgent.java:1079`,
  `KeyCheck`, `ModelCatalog` to OpenRouter), is stored through `AiKey` (Keystore), cleartext HTTP is limited to localhost
  by `network_security_config.xml`, and the log lines that mention a key print its length only.
- **Not examined in depth.** `ChatAssistantActivity` (4,100 lines) beyond the undo, settings and proposal paths;
  `VisLabEdit` / `VisLabActions` / `JoyBrushActions`; `TranscriptSynthesizer`. No UI-thread sweep of the chat was done.
