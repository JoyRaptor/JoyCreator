Fade Handle Studies

Eight ways to grab a fade-in / fade-out on a timeline clip, drawn at true device scale on both row heights the editor actually uses. Every mock is 1 SVG unit = 1 dp, so what looks small here is small on the phone.

"The tape is much narrower for images than it is with audio, and that makes the handles almost untouchable. And it's really crowded because they're right next to the trash can too. And the handles are pretty ugly. Whatever we do for one, we should do for the other, but it has to be something that looks handsome and is easy to access, and it's clear when it's working." — the brief

Measured constraints (from LayerRowRenderer.java)

76 dpAudio row height (ROW_HEIGHT_AUDIO_EXPANDED_DP)
34 dpImage / overlay row height — 14 dp when collapsed
20 × 12 dpCurrent fade hit zone (FADE_W_DP × FADE_H_DP)
16 dpTrim zone at each end (TRIM_WIDTH_DP) — trim wins ties
r 18 dpTrash slop circle (badge r 9 × 2), centred at x1−25 dp
44 dpThe touch target every one of these has to reach

The collision is real and it is arithmetic: on a 34 dp row the fade-out zone spans x1−36 → x1−16 in the top 12 dp, and the trash slop circle covers x1−43 → x1−7 across the whole row. They overlap almost entirely; the only reason it works today is that hitTestItem checks fade first — which means in that strip the trash is unreachable, and 8 dp lower the fade is unreachable. A 12 dp-tall target is roughly a quarter of a fingertip.

The eight options

01

Corner Triangle

baseline

Today's design: a 20×12 dp filled triangle tucked in each top corner, inset past the trim zone.

Audio · 76 dp row
Image · 34 dp row
+Costs zero extra space and never moves the row's layout.
−12 dp tall is a quarter of a fingertip — a third of the row on image, a sixth on audio.
−Sits inside the trash's 18 dp slop circle; one of the two always loses.
−The triangle's size never changes, so a 0.2 s fade and a 4 s fade look identical. Nothing shows it worked.
02

Ramp Wedge + Corner Dot

strong readout

A translucent wedge is painted under the whole fade region, with a round grab dot riding its top corner. The shape is the fade.

Audio · 76 dp row
Image · 34 dp row
+Fade length is legible without touching anything: longer fade, longer ramp.
+The dot is a round 44 dp target and lives inboard, well clear of trim.
−On a 34 dp row a 44 dp circle overflows the row by 5 dp top and bottom, into the 3 dp inter-row gap and the neighbour above.
−A short fade parks the dot near the edge, back inside the trim zone's argument.
03

Envelope Strip

size-independent

A fixed 28 dp control strip appears above the selected item only, carrying the envelope line and two knobs. Same strip whatever the row height.

Audio · 76 dp row
Image · 34 dp row — identical strip
+The one option whose target does not shrink with the row — 28 dp of strip plus slop reaches 44 dp on a 14 dp collapsed row too.
+Physically separated from trim and trash: zero contested pixels.
+Room for a numeric readout ("0.8s"), so "is it working" is answered in words as well as shape.
−Costs ~32 dp of vertical space while selected, and either overlays the row above or pushes it — both need care.
−Two places to look: the control up top, the effect down in the clip. Needs the in-row ramp to tie them together.
04

Whole-Edge Drag Zone

invisible

No handle at all. The leading and trailing ~25% of the clip is the fade target; drag anywhere in it. A faint tint marks the zone.

Audio · 76 dp row
Image · 34 dp row
+Enormous horizontal target and no new artwork to make ugly.
+Nothing to miss — you cannot mis-aim at a region that big.
−Vertically it is still only the row height: 34 dp on image, 14 dp collapsed. Fails the 44 dp rule.
−Steals the drag that should move the clip, and swallows the trash entirely on the trailing side.
−Undiscoverable: nothing says "grab here", so it fails "clear when it's working" at rest.
05

Tap-to-Inflate

two-step

Handles rest as small quiet dots. Tap one and it blooms to a 44 dp puck with a halo, which stays inflated until you tap away.

Audio · 76 dp row — left resting, right inflating
Image · 34 dp row
+Quiet at rest — solves "the handles are ugly" by mostly not drawing them.
+Once inflated the target genuinely is 44 dp, on any row height.
−You still have to hit the 20 dp resting dot to inflate it — the hard part is unchanged.
−Adds a mode. Two taps and a drag to do one thing, and the inflated puck lands on top of the trash on the trailing side.
06

Outboard Knob on a Stem

no collisions

The grip lifts clear of the row entirely — a 20 dp knob floating ~20 dp above, tethered by a hairline stem to the point in the clip it controls.

Audio · 76 dp row
Image · 34 dp row — knob unchanged
+Row height stops mattering — the knob is the same object on a 76 dp and a 14 dp row.
+Nothing of the row's own furniture (trim caps, trash) is within reach of it.
+The stem makes the link to the clip explicit without any label.
−Floats over the row above; with two stacked rows selected in sequence it reads as belonging to the wrong one.
−Two loose knobs in mid-air look unmoored — less "handsome" than a strip that visibly contains them.
−The top row of the timeline has nothing above it to borrow.
07

Curtain

unmistakable

A dark veil covers the fade region — literally showing the clip dimming — and the entire sloped edge of that veil is the drag surface, top to bottom.

Audio · 76 dp row
Image · 34 dp row
+For an image fade this is close to literal: the clip really does go dark.
+Nothing to aim at precisely — the whole diagonal is live.
−Dims the waveform and the thumbnail, the two things you were reading the row for.
−On a 34 dp row the diagonal is short and nearly horizontal; the band is still under 44 dp in any direction.
−The trailing veil sits on top of the trash roundel.
08

Edge Popover Scrubber

precise, modal

Tap near an edge and a floating HUD opens above the clip: a wide slider with a numeric readout. You set the fade in the popover, not on the row.

Audio · 76 dp row
Image · 34 dp row — same popover
+Most precise of the eight, and the only one that lets you type or nudge an exact duration.
+Completely immune to row height and to the trash.
−Modal: you leave the timeline to do a timeline gesture. Direct manipulation is gone.
−Still needs an in-row target to open it — the discovery problem is only moved, not solved.
−The popover hides the clips above while it is open.

Recommendation

Option 03 — the Envelope Strip, with Option 02's ramp shading left painted inside the clip

The strip is the only design whose touch target is decoupled from the thing that is broken. Every in-row option inherits the row's height, and the row is 34 dp — you cannot build a 44 dp target inside 34 dp without spilling somewhere. So stop trying: give the fades their own fixed 28 dp strip that appears above the selected item, and it is the identical control on a 76 dp audio row, a 34 dp image row, and a 14 dp collapsed one.

  • Touch. 28 dp of drawn strip plus 8 dp of slop above and below is a 44 dp band, and the knobs get a 44 dp circular zone along it. Row height never enters the arithmetic.
  • Collisions. The strip lives entirely outside the clip rectangle, so it cannot argue with the 16 dp trim zones or the trash's 18 dp slop circle. hitTestItem gets a clean early-out on the strip band before it ever reaches the item loop — no more "fade wins, so the trash is unreachable" ordering games.
  • Readability. The envelope line is a picture of the fade: the ramps get visibly longer as you drag, and there is room for "0.8 s" beside each one. Keep the translucent wedge inside the clip too, so the row still shows its own fades once the strip closes and you deselect.
  • Parity. One strip, one drawing routine, one hit test, shared by audio volume and image opacity — which is what the existing spec already asks for.
  • Looks. A contained, rounded, labelled control reads as a piece of the app; two bare triangles read as leftovers. This also answers "ugly" without adding chrome to the resting state, because the strip only exists while something is selected.

Runner-up is 06, the outboard knob — same geometry win, less code. It loses on looks and on the top row of the timeline, which has nothing above it to float into. If the strip proves too tall in practice, 06 is the fallback and shares most of the same hit-testing work.
