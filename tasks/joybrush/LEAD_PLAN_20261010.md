## Verified findings (lead read the code 2026-10-10; not phone-tested)

| # | Finding | Evidence |
|---|---|---|
| F1 | **Big pencils thrash the media window.** A dry stroke's reach is 12 × tool width (480 px per mm of `tipMax`). `MediaWindow.follow` needs pen ± reach inside a 768 px interior. For any pencil with `tipMax` ≥ ~0.8 mm this is impossible, so `moveTo` runs **every frame**: flush, then a reload of 16 tiles × up to 5 stores. It is a strong suspect for pencil lag and for seams. | `MediaCanvas.kt:276-277, 318-321`; `MediaWindowMath.kt:21,28-31`; `MediaWindow.kt:71-80` |
| F2 | **Dabs outside the window are clipped.** `follow` checks the pen, not the batch's real dirty rect, and `layerRect` clamps to the window. | `MediaCanvas.kt:277`; `MediaLayerEngine.layerRect` |
| F3 | **The look is re-rendered only for dirty tiles**, but the render shader reads neighbours (±1 px gradients, lamp march up to ~51 px). The neighbouring tile keeps a stale look, which shows as a seam at the tile edge. | `MediaWindow.kt:91-98`; `jb_media_render.frag` 69-109 |
| F4 | **Water stops dead at window edges**, and moving the window stops water. | `WetSpread.grow`; `jb_wet_flux.frag` |
| F5 | **Media on Animation boards is broken.** The auto-made MEDIA layer gets one shared cel and no frame regions, so a media stroke on an animation board lands on the shared plane. Files with a MEDIA layer that has regions are refused on open. | `GlPaintEngine.addMediaLayerStep:739-749` vs `documentForStack:707-713`; `JbCanvasView.refusalFor` |
| F6 | Smudge and fill on an armed Tile board refuse with a toast **once**, then silently do nothing. Media on a tile board paints without wrap-around. | `JbCanvasView.kt:370-380, 1231-1232` |
| F7 | Possible hairlines on the display at 256 px tile edges at fractional zoom (LINEAR + CLAMP_TO_EDGE, no neighbour texels). Needs a screenshot to confirm. | `GlPaintEngine.newTexture`; `jb_tile.frag` |
| F8 | Vector/ink core (~2,900 lines: records, replay, picker, edit session, vector eraser, CelComposer, LineChange) is **not wired to the screen at all**. There is no selection or transform UI. | grep: zero refs in `androidkit/` and `joybrush-android/` outside export |

F5 and F6 together are the most likely explanation of "different paintbrushes not working on all the boards".
F1–F4 are the likely explanation of the seams.

## Order of work (lead lane)

1. ✅ Back up the uncommitted JB-2.40 WIP: `origin/backup/jb240-media-wip-20261010` (49c87156) and
   `origin/backup/jb240-root-integration-wip-20261010` (db9411e5).
2. **Media window fix (F1–F4).** Use the batch's real dirty rect plus the shader's read halo (not 12× reach) to keep
   the window placed. Never relocate mid-frame without first painting the queued dabs. Re-render the look with a
   neighbour halo so edge tiles stay consistent. Large batches use the already-built DrySpatialPlan to split into
   frozen-input sub-windows. Proof: a GPU regression in the existing headless checker (seam pixels exact versus
   one big window), plus a counter showing zero window moves on a held big-pencil stroke.
3. **Performance instrumentation on the phone.** A Perfetto trace of a recorded fast stroke per engine
   (stamp/pencil/watercolour/oil), with GPU slices. Find the top three costs and fix them in order. 10× is the
   goal; numbers are reported, never promised in advance. Owner levers: latency budget ≤ ~1 display frame extra,
   curve error ≤ ~0.25 screen px.
4. **JB-2.40 completed**: media payload on any PAINT layer, per cel/frame (fixes F5), one undo, save/reopen. Reconcile
   the WIP backups, not a rewrite.
5. **Tile board gaps (F6)**: media wraps on Tile boards, or refuses visibly every time. No silent no-ops.
6. **Input router extraction** from `JbCanvasView` (mechanical; no behaviour change; tests plus compile). This
   unblocks the UI lane.
7. **JB-5.20 a–d** with the vector specialist: record capture, slabs, look cache, GPU line replay through the
   specialist's renderer.
8. Phone acceptance per spec; owner signs off.
