## Required coordinated scene API

These exact interfaces are a dependency, not a request to store candidate images globally:

```kotlin
RecordedScene.State.brushAssets: Map<String, FrozenBrushPngs>
Renderer.line(address, record, preset, pngs: FrozenBrushPngs?): Unit<T>
stageJoint(step, direction, frozen, frozenAssets: Map<String, FrozenBrushPngs>? = null)
stageJointProjected(expected, step, direction, frozen, frozenAssets: Map<String, FrozenBrushPngs>? = null)
```

Keep the existing renderer3arg interface and give the new4arg interface a default delegation for existing fakes. The actual engine overrides4arg. Every scene preparation must send resources from its own immutable **candidate** map; newly frozen brushes are absent from the published old root. The3arg engine callback resolves only already published resources. This applies equally to warm/cold materialization, ordinary records and captured source recipes.

Snapshot the map before external rendering callbacks, validate its exact key/path closure with `FrozenBrushRegistry.validateAssets`, and carry it through every `State` construction. Defaults inherit the old state's bundle for edits/history. Explicit candidate maps describe the complete selected definitions. New definitions and image bytes publish together only after the existing proposal succeeds. A failed/canceled proposal retains the old root and its bundle.

Undo/redo retain frozen definitions/resources that history still references; pruning must use the actual complete cursor endpoints as well as current planes. An archive exports exactly the sampled definition keys that it actually exports; it cannot export an unrelated global asset cache. Snapshot/cold loading must preserve that map and encoded budgets. The View/Cold/scene held adapter is coordinated separately with `/root/sample_tip_audit`.

## Runtime boundaries

The View owns a UI-thread `SampledTipResolver`; the engine owns a separate GL-thread resolver. Live setup passes a first selected `SampledStamp` in the immutable `TipShape` before `beginStroke`. No UI call accesses the engine resolver. Recorded replay resolves the frozen PNG bundle once, passes the resulting same `SampledTipSet` to both bounded admission and GPU replay, and uses the first replay dab's stamp in `TipShape`.

One `SampledMaskTextures` owner tracks the physical context epoch. It creates its white placeholder at GL setup, uploads one actual bounded atlas before grain bindings, and keeps it for the entire stroke. Cancel/end deletes the atlas, normal release deletes the owner, and context loss forgets names before any cancel path. All protected-name and external inventory families include atlas plus placeholder. The global placeholder is deliberately not added to `heldTextureNames()`'s drawing-content count, just as grain placeholders are excluded; doing so would make an empty initialized context falsely report lost artwork.

`setPendingLine(...,newAssets=emptyMap())` snapshots candidate assets but does not publish them. Legacy NativeLines still explicitly refuses sampled lines because it has no resource-bearing immutable scene/history root. That guard must stay until a distinct legacy adapter exists. Actual sampled line replay is enabled by the resource-bearing RecordedScene callback only. The pending map is a transport hook for the View transaction, not an authorization to add entries on contact.

## Compatibility review with the held View / scene proposal

The generator now appends `frozenAssets=emptyMap()` to `createRecordedScene`, `createCapturedRecordedScene`, and `createSavedRecordedScene`, passing the complete map to `RecordedScene.create/createSaved`. Cold loading obtains `plan.frozenBrushAssetsCopy()` and retains it through scene acceptance. RecordedSnapshot receives `expected.recorded.brushAssets`, which its held adapter filters and validates before readback.

`lineSnapshot()` exposes the actual recorded root when present, including frozen images, records, item planes and slab count; the native-only path keeps its existing snapshot. Recorded root and brush revisions remain stable between unchanged getters. A weak reference tracks the last root identity so this UI snapshot revision cache does not itself retain retired image sets. The View already clears its freeze cache on document load; a future adapter switching native/recorded modes without a load must also clear that cache before changing revision domains.

Captured-source admission overrides both signatures. Its four-argument form receives the exact candidate bundle, keeps image decoding out of the admission callback, and allows sampled stamp recipes only with the prevalidated bundle. Scene validation checks exact key/path closure and encoded budgets before invoking it; the four-argument rendering callback then performs bounded decoding. Existing three-argument direct calls resolve only published assets.

PendingLine candidate admission now checks PNG/manifest closure and the 64MiB candidate bound before retaining it. A null/rejected replacement clears the previous pending candidate. The complete document budget still belongs to scene admission before publication. No candidate resource is ever inserted in a published map by setPendingLine.

The core extra hunks preserve existing overloads and trailing-lambda meaning. New lookup overloads use frozen brush IDs and pass resolved sets to InkTiles/InkReplay. Missing sampled resources explicitly refuse selection/erase/preview instead of silently producing empty measured geometry. Region export preserves the existing default refusal callback. Sampled native bilinear support expands conservative selection/erase half-widths and tile extents; these are bounds rather than exact alpha hit tests.

Remaining activation gap: PendingLine.assets is a bounded transport only; current live `beginStroke/endStroke` require local paint and do not consume a pending sampled line into a bound RecordedScene. The legacy NativeLines branch deliberately refuses that line. Wiring a new captured contact into an accepted joint line root is a separate Lead-owned application transaction; these review fixes do not claim live editable sampled strokes are activated. The View's legacy line load/edit/save and diagnostic probe retain their corresponding guards. The host must install its stable immutable PNG provider on main/tuning/preview Views, and region/selection/erase callers must supply the new ID-keyed sampled lookup before enabling those routes.

The generator was rerun successfully after this compatibility review. No canonical source, build, device or other chat was touched. These held sources still require compilation and transaction tests after Lead applies/rebases them together with the scene proposal.

Do not enable sampled tips on smudge: the existing pickup sampler units2..10 overlap the sampled atlas unit3. Schema validation currently requires `engine=stamp`; direct engine callers need the same guard. Watercolour/tuft also remain separate.

## Budgets and accounting

Encoded ownership is already bounded to16MiB/PNG,32MiB/set and64MiB/document (including manifest); max2048dimension and4Mi ordered decoded source pixels are checked before decoding. Atlas storage is independently bounded to8Mi R8 pixels and the actual device texture limit. The engine's diagnostic reports a conservative CPU decoded-mask charge (cached replay set plus live look; sharing may be counted twice) and active R8 atlas bytes. Stroke end drops the live set reference from `look`.

These fixed resources stay outside the existing mutable **tile** budget, which already excludes paper/grain resources. They must be shown as a separate budget family. Preparation also temporarily holds the immutable atlas R8 array, its exported copy, and Android's direct upload buffer (up to24MiB total across those3 buffers); PNG decoder temporary ARGB/Bitmap memory has its own preflight bound. Do not describe the mutable tile limit as a whole-engine memory limit. Avoid any heavy GPU run while Lead owns the shared build/RAM lock.
