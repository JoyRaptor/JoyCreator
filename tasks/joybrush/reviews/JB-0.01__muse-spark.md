## Finding 1 (Medium): `StrokeSmoother` accepts any `screenPerDoc`, including 0 — replay with 0 yields Inf/NaN coordinates that poison everything downstream
Proof: `joybrush/core/.../input/StrokeSmoother.kt:47` — `amount` is coerced (`amount.coerceIn(0f,1f)`) but `screenPerDoc` is stored unchecked. `feedPath` multiplies by it (`:113`), `smoothedAt` divides by it (`:177-178`). With `screenPerDoc = 0f`, every output x/y is `0/0 = NaN` or `v/0 = ±Inf`. Those flow into `DabPlacer` (`hypot(Inf)=Inf`, `t = along/Inf`, `untilNext = -Inf`) and then `TipMath`/`RefCanvas`, writing NaN into tiles. `StrokeRecord.screenPerDoc` round-trips any float through the codec (`StrokeCodec.kt` stores `f32` raw, test even covers NaN timeMs), and nothing in `StrokeRecord`'s `init` (`StrokeRecord.kt:27-29`, only rejects `predicted`) or the codec validates it — so a 0/NaN zoom persisted today corrupts the stroke at replay (JB-0.08/JB-5.01). `JbCanvasView` passes hardcoded `1f` today, which is why tests pass. Fix (Lead/builder call, not mine): `require(screenPerDoc.isFinite() && screenPerDoc > 0)` in `StrokeSmoother` and/or `StrokeRecord`.

## Finding 2 (Medium): `Curve` accepts non-finite points — NaN/Inf brush values become NaN/Inf paint with no error at this layer
Proof: `dynamics/Curve.kt:19-23` — only `require(points.isNotEmpty())`; no finiteness check on x/y. A `Curve(listOf(0f to Float.NaN))` builds a LUT of NaN; `eval` returns NaN for every input. This is the low-level enabler of the JB-0.03 chain (file with `"base": 1e999` decodes to `+Inf`, passes `BrushValidate`, `Dynamics.eval` returns `Inf`, `DabPlacer.step` becomes `Inf`, the stroke stalls after one dab — see JB-0.03 review). `Curve.eval` correctly coerces finite out-of-range x (`:28`) and maps NaN x to `lut[0]` (`:27`), so the hole is strictly non-finite *points*, not inputs.

## Finding 4 (Low): `DirectionTracker` turns NaN on (Inf tilt + NaN azimuth) instead of falling back
Proof: `DirectionTracker.kt:57` — guard is `s.hasTilt && s.hasAzimuth && s.tilt > tiltThreshold`. `tilt = +Inf` passes (`hasTilt` is `!isNaN`, `Inf > 0.17`), then `dx = cos(NaN) = NaN`, and `update` returns `atan2(NaN,NaN) = NaN` — a poisoned direction that `TipMath.coverage` turns into NaN coverage (see JB-1.01 review). Hardware never reports Inf tilt, and `MotionEventSamples` coerces pressure but passes tilt raw, so reachability today is nil; a `!tilt.isFinite()` in the guard would close it for free.
