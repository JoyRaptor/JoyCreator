## Not reproduced

- "a `0x20|0x40` mask collapses into one slot" — not reproduced. `PenButtons.kt:456-459` walks `i in 1..31` and emits one `PenButton` per set bit, ascending; `PenButtonsTest.kt:27-33` pins both orderings.
- "an unknown bit is dropped" — not reproduced. The same loop has no whitelist, so 0x100, 0x8000 and 0x80000000 all become slots, and `displayName` names them.
- "an unknown action name is lost on the SECOND save" — not reproduced. `PenButtons.kt:343` reads `unknown` first and `:239` writes it back re-parsed; `PenButtonsTest.kt:297-337` and `:340-368` pin the exact-once and whole-entry rules and go red if the read of `unknown` is deleted.
- "the long-press fires twice, once as long-press and once as drag-off" — not reproduced. `holdFired` is posted once per DOWN, `watchForHold` calls `stopHoldWatch()` before re-posting (`JbCanvasView.kt:844`), and `stopHoldWatch` is reached on the first MOVE past slop (`:831-839`).
- "the second-finger cancel is spoofed by a jittery first sample" — not reproduced. The watch is keyed on `holdPointer`'s index and `ACTION_POINTER_DOWN` is not `ACTION_MOVE`, so it stops the watch before any slop test (`:831-839`).
- "an R10 constant is used raw or declared pre-scaled" — not reproduced. Every dp constant in `Eyedropper.kt` is multiplied by density at its use site (`Eyedropper.kt:66-67`, `JbCanvasView.kt:865`, `:1433`, `EyedropperRingView.kt:39-40`, `:44`, `:57`, `:82-83`). `RING_DP / 2f` is a radius, and the arc box is inset by `thick / 2f`, so the outer edge lands exactly on `r` — the outer ring is 44 dp as Decision 5 asks.
- "the sampled coordinate is off by one" — not reproduced. `JbCanvasView.kt:193` flips y as `viewH - 1 - y`, the read happens after `engine.draw` on the GL thread in `onDrawFrame` (`:654-659`), and it reads the composited surface, so there is no tile-edge or flip error to make. `GlPaintEngine.readPixel`'s own `docX - tx * size` arithmetic is correct too — it is simply never called.
- "a cancelled eyedropper's colour is pushed to the app-wide recents" — not reproduced. `onColorPicked` (`JoyBrushActivity.kt:408`) is only reached from `take()` (`JbCanvasView.kt:899-902`), which `eyedropEnd` calls only when `took` (`:889`, `:896`). `ColorRecents.push` also de-duplicates by RGB (`studiokit/.../ColorRecents.java:50-58`), and it is the one app-wide list (D.02c).

## What I could not check

- Whether the Note 9 S Pen really reports contact as `0x01` and its barrel buttons as `0x20`/`0x40`. Every bit-level finding above assumes the numbers in R42 and the spec's Contract; the device check is still owed and one KDoc claim about it is wrong (see MINOR 9).
- The lasso state machine and R42's "a lasso ALWAYS closes itself when the pen lifts", including a button released before the pen lifts. No lasso exists in either row — `JbCanvasView.kt:697-698` says the hold action is not wired — so there is nothing here to break and nothing to clear.
- The settings screen that will populate `canvas.penButtons`, expose "Detect a button", and write `penbuttons.json` (chrome row 2.01). Without it I cannot tell whether an unbindable-but-storable tip bit would be reachable by a person; it is reachable by any future screen and by a hand-edited file today.
- Whether `ColorPickerDialog` pushes to `ColorRecents` itself. `pushInto` de-duplicates by RGB so it cannot double-add, but I did not read the dialog.
- Runtime GL and driver behaviour on the Note 9: I ran nothing, so the framebuffer-read timing, the density values, and the real button bits are unverified by execution.
