## Finding and boundary

Zero-replay **display load** is possible from the stored cel looks and physical sources. Zero-replay creation of an **exact per-line affected-tile index** is not possible from the current serialized data: the file contains no per-line footprints. Keep that index explicitly unresolved at load, and materialize it transactionally before an operation needs it. Do not substitute the cel's look union or a CPU bounds rectangle for a line's canonical GPU footprint.

The present `RecordedScene.create` cannot be used for fast load. It calls `render` on an empty state; `render` calls `renderer.line` for every record, derives footprints from returned unit tile keys, creates complete plans, and composes looks. See [create](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/lines/RecordedScene.kt:310), [every-record rendering and indexing](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/lines/RecordedScene.kt:264).

## Minimum safe loaded runtime state

Recommended changes are runtime-only; this plan does not propose an archive schema revision.

1. Retain detached physical `RecordedCel` values for all loaded addresses, raw records at the saved seqs, every bottom/upper slab at its saved seq/op, and frozen document brushes. Apply the document-to-engine shared-plane mapping once and retain it explicitly. Preserve masks/plain/media payloads alongside the recorded state; do not route them through a display projection. `RecordedCel` already validates scoped IDs, positive unique line seqs, slab/line seq separation and source ownership; `nextSeq()` accounts for lines and slabs and refuses exhaustion. See [RecordedCel invariants](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/RecordedCel.kt:20), [nextSeq](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/RecordedCel.kt:39), [CelLayout stack decoding](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/LineRules.kt:108).
2. Keep a separate owned display map of uploaded saved `.look.rgba` textures and its **declared cel union**, independent of any materialized canonical units. The saved index must survive while the unit cache is empty; the present `savedLookKeys` implementation would return an incorrect empty index in a lazy scene. A look overrides the displayed composition for that physical tile; it is never written into the bottom slab store. Plain tiles with no line look use their plain physical sources; slab-only stacks requiring composition may use the existing ordered compositor without replaying lines. Refuse unsupported operators before replacement rather than showing only the bottom slab. The GPU compositor currently accepts five operators, whereas `SlabOps.known` also accepts other document blend names. See [GPU operator set](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/GlPaintEngine.kt:1702), [schema operator set](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/doc/DocModel.kt:212).
3. Represent canonical line units/footprints as **unmaterialized**, not empty. A genuinely materialized line with no output has an explicit empty footprint. Do not build `RecordedTilePlan` until every record for that plan has a known footprint; the existing constructor correctly refuses missing entries. See [footprint requirement](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/RecordedTilePlan.kt:42).
4. Add a saved-state installation path separate from the eager scene factory. Validate cheap schema/payload identities first, stage uploads and source ownership, then publish all document/engine/UI references together. Loading must issue zero `Renderer.line`/`InkReplay.replay` calls and must not push history. Texture allocation or validation failure must leave the previous document and archive untouched. Root owns this joint publisher; this audit does not authorize relaxing its legacy/media/structural guards.
5. Pin materialized units/indexes to the actual document paper and physical clipping context. The current scene renderer rejects stale document/paper, playback and tiling context. Keep the same generation and resource ownership protections during lazy materialization, and forget old GL names on context loss. See [captured renderer context](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/GlPaintEngine.kt:1619), [forget/close](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/lines/RecordedScene.kt:219).

## Lazy materialization and exact edit invalidation

The minimum safe first implementation is **lazy by physical cel**. On the first visual edit, bake, deletion, write-order decision or recomposition touching an unindexed cel, stage canonical GPU units for every unindexed record in that cel, using each unchanged raw record and its own frozen brush. This does not require replay of other physical cels. Retain old scene/display/history until the entire required cel materialization succeeds.

Why replaying only the selected line is insufficient: the file supplies neither that line's old footprint nor which unchanged lines overlap a changed tile. The saved cel union cannot identify them. A source unit is authoritative only after the actual GPU renderer returns its tile keys, after watercolor pooling and the renderer's physical-cel filtering. See [unit creation/filtering](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/GlPaintEngine.kt:1634).

After materialization, build a complete old plan from canonical keys; render the edited record into a fresh unit; build the new plan; compute affected tiles from both plans, retaining old keys for moves/deletes. Compose only those keys from strictly ordered sources with their original seq and operator, then commit the edit and history together. Never use a saved composed look as a line unit, apply brush opacity a second time, or bake it at a guessed seq. Existing `RecordedTilePlan.affectedTiles`, `RecordedEdits`, and staged scene publication provide the correct boundaries. See [affected tiles](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/RecordedTilePlan.kt:69), [seq-preserving replacement](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/RecordedEdits.kt:23), [staged publication](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/lines/RecordedScene.kt:96).

Metadata-only lock/group edits need not trigger replay or replace saved looks. Current `renderingRecord` permits unit reuse for those fields, but the current tile plan compares whole records and still invalidates their tiles. Lazy support needs an explicit nonvisual metadata route or matching rendering comparisons rather than assuming existing `stage` is already zero-replay. See [renderingRecord](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/lines/RecordedScene.kt:307), [plan comparisons](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/RecordedTilePlan.kt:83).

An optional later cache eviction can discard canonical texture units while retaining **already measured** footprints and source operators; then composition need only rematerialize known contributors to affected tiles. That is a subsequent runtime cache change, not information currently recoverable from an archive at load.

## Saved-look completeness: an existing limitation, not a solved gate

`JbArchive.read` validates declared look payloads in both directions, brush identities, structural line rules and seq ordering without replay. It does **not** prove that the declared look union includes every line-crossed tile. `LineRules.lookProblems` on write rejects declared keys that no drawable line reaches; it does not test missing crossed keys, returns early for an empty look list, and bypasses the geometric check for CPU-refused lines. See [read validation](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/io/JbArchive.kt:692), [no-replay read](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/io/JbArchive.kt:746), [write check](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/io/JbArchive.kt:337), [lookProblems implementation](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/LineRules.kt:74).

Consequences:

- The normal `RecordedScene` → `RecordedSnapshot` producer provides an actual complete index, but generic archive acceptance alone is not proof of that producer invariant. No stored provenance/completeness marker exists in the inspected types.
- Empty `Cel.looks` is also valid for records with no dabs; it cannot universally mean corruption. Existing tests preserve such a record with an explicit empty runtime index. See [no-dab archive test](/C:/Temp/jb-live-current/joybrush/androidkit/src/test/kotlin/cc/joycreator/joybrush/androidkit/gl/lines/RecordedSceneSnapshotTest.kt:147).
- A no-replay loader can display exactly the declared saved image and retain all source data, but cannot certify that image equals replay for every accepted archive. On first materialization, validate the actual canonical-key union against the saved index before allowing writes; a mismatch must preserve the original file and explicitly require reconstruction/refuse the transaction.
- If the product requires certified full display for **every** older/imported archive before any first frame, that cannot be promised together with zero replay using the inspected schema. Keep the existing screen refusal until root chooses the acceptance boundary. This plan does not invent footprint metadata, claim byte provenance, or disguise a slow compatibility reconstruction as fast load.

## Unsupported replay: preservation and refusal

Fast saved-image display must not evaluate missing grain or a watercolor cap. Preserve saved look bytes, raw records, original seqs and brush definitions even when a future editable unit cannot be produced. Editing/baking an affected unindexed cel refuses as a whole if one required record cannot materialize; do not publish partial units, move history, replace the saved look, drop the record or silently rasterize it. Keep unchanged payloads available for snapshot/copy/recovery.

The existing GPU path requires supported stamp/watercolor engines, procedural stamp tips, no whole-stroke shaping, actual paper resources, and exact legacy pose where needed. Recorded grain must refuse missing requested pictures instead of adopting the ordinary missing-grain OFF fallback. Watercolor replay refuses over 6,000 dabs rather than accepting truncated editable truth. See [GPU replay gates](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/GlPaintEngine.kt:1524), [asset checks](/C:/Temp/jb-live-current/joybrush/androidkit/src/main/kotlin/cc/joycreator/joybrush/androidkit/gl/RecordedGrainAssets.kt:7), [watercolor cap refusal](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/InkReplay.kt:113).

CPU rendering is not a fidelity fallback: it explicitly refuses watercolor image/pooling and tip grain, and reports paper grain as an omission. Consequently the archive write check can pass saved watercolor looks without replaying their GPU units; it does not establish editability. See [CPU refusals/omission](/C:/Temp/jb-live-current/joybrush/core/src/commonMain/kotlin/cc/joycreator/joybrush/core/vector/InkTiles.kt:55).

Missing declared payload bytes already refuse archive open before renderer replacement. A cache-free or incomplete legacy drawing needs an explicitly separate reconstruction path when supported; if reconstruction cannot reproduce its contents, refuse before replacing the current drawing and preserve its file. Do not remove the current screen/archive/export refusals merely because a saved-look factory exists.
