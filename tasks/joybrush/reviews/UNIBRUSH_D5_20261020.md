# Unibrush D5: sampled tips and frozen image resources

Brush v16 adds an explicit nullable sampled-tip recipe. Existing opaque import payloads and
legacy brushes retain their old rendering. New recipes use ordered PNG images, sequence/random/
pressure/direction selection, independent rotation/spacing jitter, inversion and alpha/luminance
coverage. Selection is indexed once per placed dab; scatter shares the selected immutable mask.
Image randomness consumes no legacy placement, colour or scatter draws. Missing resources refuse
the recipe rather than substituting a circle.

CPU and GPU use native image aspect and bilinear coverage. A transparent one-pixel atlas gutter
and explicit source-support guard prevent neighbouring-image bleed. Tiny images include their
full bilinear support in tile/vertex bounds. Explicit quad/profile/fade combine with the image
once. Pixel-centre coordinates avoid vertex rasterization rounding shifting sharp texels.

The original 17n-float instance prefix remains unchanged. An optional 4n image tail follows fade,
quad and RGB tails; attribute13 is reset after the draw. The atlas binds on unit3, and disabled
draws reset the mode and bind a safe placeholder. This uses14 attributes, within GLES3's minimum16.
The conservative expanded fragment uniform count is184 vectors, within its minimum224.

Frozen brush identity includes actual PNG bytes. Archives retain logical paths in an explicit
manifest and deduplicate content-addressed PNG blobs. Saves validate before writing output;
read/reopen/resave need no installed brush library. Paths, exact resource closure, PNG chunks/CRC,
dimensions, complete ordered decoded pixels and encoded ownership are bounded. Limits include
2048px dimensions,4Mi ordered source pixels,16MiB per PNG,32MiB per brush and64MiB per archive.
Android decoding preflights all sources before Bitmap allocation, processes one Bitmap at a time
and recycles it. Atlas ownership distinguishes current-context release from context-loss abandon.

New materializing import APIs convert actual ABR sample pixels to PNG, retain Procreate/Krita
source PNGs and expose explicit coverage options. Existing import signatures retain compatibility.
These APIs still need the D9 library/import host UI.

engine/codec/GPU proofs do not establish those application transactions or Note9 performance.
