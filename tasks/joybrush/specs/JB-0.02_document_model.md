## Goal
The in-memory shape of a Joy Brush drawing and its `document.json`. Everything else (renderer,
save/open, animation, export) builds on this. No pixels here — pixel tiles and stroke files are
referenced by path and handled by later specs.

## Design (decided — do not change)
- A **document** is an unbounded canvas at one pixel density. It has **paper** (a setting, not a
  layer), an ordered **layer stack**, and **boards**.
- A **board** is a named rectangle on the canvas with a kind: `CANVAS`, `ANIMATION`, `SPRITE`,
  `PUPPET`, `CHARACTER`. It defines export bounds. A new document has one CANVAS board.
- A **layer** is `PAINT` (pixels are the truth, stored as 256×256 tiles) or `INK` (stroke records
  are the truth).
- **Animation without a second layer system:** a layer is either static, or *animated in* one
  ANIMATION board. A static layer has one cel. An animated layer has one cel per frame of its board
  (a frame may share a cel with another — that is how "hold" and "duplicate as link" work). Static
  layers show behind/in front of every frame (a held background).
- Every id is a string (UUID generated by the caller; tests may pass fixed ids).

## Contract to build (verbatim)
```kotlin
package cc.joycreator.joybrush.core.doc

import kotlinx.serialization.Serializable

const val DOC_FORMAT = "joybrush.document"
const val DOC_VERSION = 1
const val TILE_SIZE = 256

@Serializable data class RectPx(val x: Int, val y: Int, val w: Int, val h: Int)

@Serializable data class Paper(
    val color: String = "#FFFFFF",          // #RRGGBB
    val textureId: String? = null,          // a grain asset id, null = plain
    val textureScale: Float = 1f,
    val includeInExport: Boolean = false,   // the "Include paper" checkbox default
)

@Serializable enum class BoardKind { CANVAS, ANIMATION, SPRITE, PUPPET, CHARACTER }

@Serializable data class Frame(
    val id: String,
    val holdFrames: Int = 1,                // shown for this many ticks of the board's fps
)

@Serializable data class SpriteGrid(val cols: Int, val rows: Int, val cellW: Int, val cellH: Int)

@Serializable data class Board(
    val id: String,
    val name: String,
    val kind: BoardKind,
    val rect: RectPx,
    val clipToBoard: Boolean = false,
    val fps: Float = 12f,                   // ANIMATION only
    val frames: List<Frame> = emptyList(),  // ANIMATION only, in play order
    val grid: SpriteGrid? = null,           // SPRITE only
)

@Serializable enum class LayerKind { PAINT, INK }
@Serializable enum class BlendMode { NORMAL, MULTIPLY, SCREEN, OVERLAY, ADD, DARKEN, LIGHTEN, ERASE_BELOW }

@Serializable data class Cel(
    val id: String,
    val tiles: List<String> = emptyList(),  // PAINT: tile keys "tx_ty" that exist (sparse)
    val strokesFile: String? = null,        // INK: path inside the document zip
)

@Serializable data class Layer(
    val id: String,
    val name: String,
    val kind: LayerKind,
    val visible: Boolean = true,
    val locked: Boolean = false,
    val opacity: Float = 1f,
    val blend: BlendMode = BlendMode.NORMAL,
    val animatedIn: String? = null,         // board id, or null = static
    val cels: List<Cel>,                    // static: exactly 1; animated: ≥ 1
    val frameCel: Map<String, String> = emptyMap(), // animated: frame id → cel id
)

@Serializable data class JbDocument(
    val format: String = DOC_FORMAT,
    val version: Int = DOC_VERSION,
    val id: String,
    val name: String,
    val paper: Paper = Paper(),
    val boards: List<Board>,
    val layers: List<Layer>,                // bottom → top
    val activeLayerId: String? = null,
    val activeBoardId: String? = null,
)
```

Plus these functions (in `doc/DocOps.kt` and `doc/DocJson.kt`):
```kotlin
object DocJson {
    fun encode(doc: JbDocument): String      // pretty-printed, stable key order
    fun decode(json: String): JbDocument     // throws DocException; unknown keys are IGNORED (forward compat)
}
class DocException(message: String) : Exception(message)

object DocOps {
    /** A new document: one CANVAS board at (0,0,w,h) named "Board 1", one PAINT layer "Layer 1" (static, one empty cel). */
    fun newDocument(id: String, name: String, w: Int, h: Int, ids: () -> String): JbDocument
    /** Every problem found (empty = valid). See Validation below. */
    fun validate(doc: JbDocument): List<String>
    /** The cel a layer shows on a frame: static → its only cel; animated → frameCel[frameId]; null if none. */
    fun celFor(layer: Layer, frameId: String?): Cel?
    /** Tile key helpers: key(3,-2) == "3_-2"; tileOf(pxX, pxY) floors to TILE_SIZE (negative coords too). */
    fun key(tx: Int, ty: Int): String
    fun tileOf(px: Int, py: Int): Pair<Int, Int>
}
```

**Validation rules** (each failing rule adds one readable message):
1. `format == DOC_FORMAT`; `version <= DOC_VERSION` (a NEWER version is an error: "document is from a newer Joy Brush").
2. Board ids unique; layer ids unique; cel ids unique within a layer.
3. Board rect `w > 0 && h > 0`.
4. ANIMATION boards have ≥ 1 frame; frame ids unique; `holdFrames ≥ 1`; `fps` in 1..60.
5. SPRITE boards have a grid with cols, rows, cellW, cellH all ≥ 1.
6. Static layer (`animatedIn == null`): exactly 1 cel and empty `frameCel`.
7. Animated layer: `animatedIn` names an ANIMATION board; every frame of that board has an entry in
   `frameCel`; every value names a cel of this layer.
8. PAINT cels have `strokesFile == null`; INK cels have empty `tiles`.
9. `activeLayerId` / `activeBoardId`, if set, exist.
10. `opacity` in 0..1; paper color matches `#RRGGBB`.

## Tests (`doc/DocModelTest.kt`)
1. `newDocument` → validate() is empty; one board, one layer, one cel.
2. encode → decode round trip equals the original (for a document with every board kind and an
   animated INK layer with 3 frames where frames 2 and 3 share a cel).
3. decode ignores an unknown key (`"future": 1`) at top level and inside a layer.
4. decode of `version: 2` succeeds but validate() reports the newer-version message.
5. One test per validation rule 2–10 (a broken document produces exactly one message).
6. `celFor` static/animated/missing frame.
7. `tileOf(-1, -1) == (-1, -1)`, `tileOf(255, 256) == (0, 1)`, `key(3,-2) == "3_-2"`.
8. Encoding is stable: encoding the same document twice gives identical strings.

**Command:** `./gradlew -p joybrush :core:jvmTest` (this standalone build is the one gradle command
Joy Brush agents may run — ROADMAP.md §2). Pass = BUILD SUCCESSFUL, DocModelTest 0 failures.

## Questions

## Lead rulings 2026-09-28

Rulings from Claude (Lead) after the builder's adversarial audit. All five are implemented and each
has its own test. They amend the contract above; where they disagree with it, they win.

1. **`TILE_SIZE` must be the engine's constant, not a second copy.**
   `const val TILE_SIZE = cc.joycreator.joybrush.core.paint.Tiles.SIZE`. `Cel.tiles` holds the keys the
   engine wrote with `paint.Tiles`; two independent `256` literals can drift, and every tile in every
   saved document would then point somewhere silent and wrong. The drift test is kept.
   → `tileSizeIsTheEngineTileSizeNotASecondCopy`

2. **New rule 11: a document needs at least one board and at least one layer.**
   A document with nothing in it is not a document. Reported as one message per thing missing.
   → `rule11_aDocumentNeedsABoardAndALayer`

3. **Rule 7 gains its converse: every KEY in an animated layer's `frameCel` must be a frame id of its
   board.** The rule already walked board → `frameCel`; it never walked `frameCel` → board, so a
   mapping for a frame that does not exist survived validation forever, and deleting a frame left its
   mapping behind as junk. Only checked when the layer's board exists and is an ANIMATION board, so a
   document broken in one way still reports one problem.
   → `rule7_aFrameMapMayNotNameAFrameThatDoesNotExist`

4. **Rule 10 also checks `paper.textureScale`: over 0 and no more than 64.** Zero hides the paper and
   a huge scale stretches one texel across the page. The lower bound is exclusive; `NaN` is rejected
   explicitly because it answers false to every comparison.
   → `rule10_paperTextureScaleHasToBeSane`

5. **`newDocument` requires `w > 0 && h > 0`.** A document with no room cannot be drawn on. A caller
   making a document is a program and should hear about it at once, rather than getting a document
   that only fails later in `validate`.
   → `newDocumentRefusesADocumentWithNoRoom`

Also approved and left in: **`DocJson.encode` sorts `frameCel` by key before writing** (the
`canonical()` pass). The audit proved by probe that without it two logically identical documents
produced different bytes whenever the map was built in a different order — and a `.joybrush` is a file
people diff and sync. Sorting loses nothing: play order is `Board.frames`, not the order of these
keys, and object keys are already stable because kotlinx writes properties in declaration order.
→ `encodingIsStableWhateverOrderTheFrameMapWasBuiltIn`

The builder also noted, and the Lead did **not** rule on, that `decode` never validates on purpose: a
document from a newer Joy Brush must still decode so `validate` can explain the version problem in
words. `DocJson.decode` and `DocOps.validate` are therefore a pair, and callers should use both.
