# Premium Motion Blur for Joy Creator Studio

Independent implementation proposal · November 22, 2026 · Galaxy Note 9 performance floor

## Recommendation

Build one **Motion Blur** effect for clips, sprite and puppet layers, and Studio’s existing **Effect Layer**. It should use motion data from each source. Studio already knows how a keyed object, camera, sprite mesh or puppet moved. For ordinary footage, Studio estimates the movement between decoded frames. Both paths share the same shutter controls, timing rules, and compositing behavior.

The first phone proof should be a zooming title and an articulated puppet over moving video. That forces the feature to handle radial motion, curved limb paths, transparency, and different motions in the same shot. A translation-only demo would pass without proving any of those.

The Note 9 goal is sustained 720p/30 preview from a defined 1080p project and high-quality 1080p export. Native parameters and timing stay fixed as the phone changes preview quality. Footage that has already been analyzed should play with blur. New footage should remain editable while analysis catches up. Export uses a fixed quality policy so device temperature, cache state, and preview history cannot change the look.

## What the artist uses

**Studio → Effects → Motion Blur** on an Effect Layer, video clip, sprite, or puppet. **Avatar Studio → Preview → Motion Blur** offers the same shutter language for the puppet and hands it to Studio with the editable character or recorded performance. SpriteLab can offer the same preview control after the Studio sprite adapter is proven.

An Effect Layer has a time span, keyframes, visibility, and the existing effect stack controls. Its default scope is **Layers Below** within its compositor stack. An included stationary title stays clean because its own motion is zero. Put a moving caption above the effect, or protect it with the target picker, to keep it sharp. A clip instance can blur footage pixels, the clip’s keyframed transform, or both. In Both, couple the motion in one trajectory or exposure and apply the transform at each sample time. Two independent blur passes otherwise distort the shutter and can double-count motion. When a clip or puppet already has Motion Blur, the Auto effect layer skips that producer by default. Explicit effect stacking remains possible with a clear inspector indication.

## One shutter and a consistent timeline

Use project output cadence for exposure length and real source presentation timestamps for footage motion. Let T be the rational output frame period and t the output frame’s project timestamp in microseconds. Open at t + Phase/360 × T and close Angle/360 × T later. Centered sets Phase = −Angle/2, Trailing sets Phase = −Angle, and Leading sets Phase = 0. At 30 fps a centered 180° shutter spans approximately −8.33 to +8.33 ms. Sample midpoint strata with fixed weights. Evaluate the shutter controls at t and evaluate motion, continuous transforms, and selected upstream animated inputs at shutter sample times. For a single-frame sample, evaluate exactly at t.

Event boundaries are explicit. A trim, hard cut, source discontinuity, sprite/viseme swap, held-key jump, tracking reacquisition or authored teleport suppresses invented trajectories. Split the sampling domain where appropriate and use only its valid portion, with normalized weights and center-frame fallback if the interval is empty. An ordinary sprite hold can still move in world space. Continuous ping-pong turns use the true reversed path if the endpoints meet. A looping wrap is a cut unless the producer identifies a continuous seam. Dissolves evaluate their two source clips independently and apply the authored transition, in stack order, without using one shot as the other’s motion donor. Freeze, slow motion, reverse and speed ramps go through the project time map. A 180° shutter stays 180° at 23.976, 24, 29.97, 30 or 60 fps.

Use absolute project time plus resolved source PTS, clip identity and continuity segment. Avoid rounding sample time to the existing millisecond effect uniform before evaluating animation. Seeking, looping playback, changing source, backgrounding and context loss invalidate live texture history and pending jobs. Valid source-space analysis can still be reused after a seek. Cancel stale work with generation IDs. Offline evaluation must be reproducible in a range export, isolated still, full export or reverse-order inspection.

## Three producers, one compositor

### 1. Keyframes, sprites and Avatar Studio

Evaluate the existing animation at shutter times. For an affine transform, map positions from a reference pose to sampled poses with the full inverse/forward matrices, including pivot, rotation and scale. A fast zoom produces longer radial paths near the edge and effectively zero motion at its pivot. Use projected vertex trajectories for perspective and mesh warp. Tessellate where appropriate. Use a midpoint or a second segment when direction or speed changes sharply, and actual subframe renders when curvature, overlap or topology invalidates the approximation.

For a rig, use a stable part/mesh ID, parent hierarchy, z-order, alpha and matched vertices. A forearm or a Bézier limb strip needs vertex motion along the whole bend. A single hand pivot vector cannot represent an arcing point or a changing silhouette. Reuse cached atlas textures and avoid constructing a bitmap per sample. Sprite cells preserve their authored held timing and pivot metadata. An optional anchored smear needs corresponding landmarks or mesh, including for variable-sized cells. A plain filmstrip receives transform blur and no automatic shape matching in the first release. Two unrelated hand, mouth or head-view drawings must not be morphed into each other when the cell changes.

Studio’s native puppet path already exposes a resolver and recorded parameter tracks. Give the Android Avatar Studio redesign an adapter contract for deterministic pose evaluation, rather than making Motion Blur depend on the web pilot’s internal objects. Make pose hysteresis, spring/drag state, IK and seeded secondary motion sampleable. Use fixed-step checkpoints or recorded resolved state for stateful behavior. Shutter evaluation can read cloned/replayed state and must never advance the live simulation once per tap. Live tracking only knows arrived poses. While performing, use available history for a causal trailing preview and show that mode. Recorded performance uses the chosen timing and can reconstruct centered exposure from nearby recorded poses.

### 2. Ordinary video

Analyze neighboring decoded frames in source space, keyed by real presentation timestamps, before applying transforms and unrelated overlays. Use hardware decode to a surface and import to GPU-owned textures. Probe two interchangeable estimators on the same clips and both phones: **GPU coarse-to-fine luma matching with local subpixel refinement** and **CPU OpenCV DIS** on low-resolution luma if the copy and CPU cost fit. Compare both throughput and shot quality. A sample implementation can start with 1/4 width and height, coarse pyramid search, overlapping patches, bidirectional estimation and edge-aware upsampling. Motion vectors have a documented sign, source-pixel unit and PTS interval. Convert to project space when rendering.

Represent forward and backward flow, confidence and discontinuities. Confidence combines forward/backward consistency, patch ambiguity, texture and photometric residual. Detect cuts before using a field. Flag flashes, dupes, long PTS gaps, occlusions and fast whip pans separately for testing. A robust global affine fit can fill a reliable camera-moving background. Local motion takes priority for independently moving objects. On uncertainty, soften the effect locally or keep the original center pixels. For foregrounds, prioritize consistent coverage and visibility with a matte when available. Avoid neighbor-vector bleed across an edge and reject inconsistent donors. Give static pixels an exact passthrough when there is no valid motion.

During playback reconstruct from the available fields with edge-aware weighted sampling. In High export, use the same flow data plus neighboring decoded frames to reconstruct intermediate images bidirectionally where reliable. Warp color and coverage together, reject disoccluded donors and keep source pixels when reconstruction is ambiguous. Higher sampling also improves authored transforms, without re-decoding once per tap. Existing image motion blur remains in the footage, so the effect adds exposure and can amplify existing smearing. Strong compression, reflections, repetitive textures and completely hidden surfaces limit what a two-frame estimate can recover.

Decode sequentially with bounded lookahead and a sliding window. Persist only versioned, quota-managed analysis chunks, never the original pixels or cache identities in project JSON. Include source fingerprint, orientation/crop normalization, source time/PTS pair, estimator revision, vector-detail policy and analysis resolution in cache keys. Color changes and shutter edits reuse raw flow. Trim/retime changes remap the time domain and boundaries, while the same valid source pair can reuse its field. For a 1080p source, two quarter-width/quarter-height RG16F vectors plus R8 confidences use about 1.24 MiB per pair before padding or compression. At 30 fps five minutes would use about 11 GB. Keep only a small active window in RAM. Start with a 256 MiB disk quota and test quantized, compressed short chunks. Warm the visible range first and support cancellation, eviction and recovery. [Android SurfaceTexture timestamps and transforms](https://developer.android.com/reference/android/graphics/SurfaceTexture) · [OpenCV DIS reference](https://legacy-docs.opencv.org/4.x/de/d4f/classcv_1_1DISOpticalFlow.html)

### 3. Compositing and effect scope

An Effect Layer needs access to the stack prefix it covers, or equivalent producer-aware render passes. With crossing objects, compositing separately exposed layers can yield incorrect coverage. In High export, evaluate and composite the selected scope for each shutter sample, then average the premultiplied pixels and place the result at that effect-stack position. Respect layer order, clipping, masks and blends per sample. When a blend mode or crossing depends on an excluded underlay, include it as a read-only compositing input, or explicitly constrain the effect scope until render-graph support exists. Keep unrelated overlays above the effect outside the temporal passes. Use per-sample transforms for attached masks and screen coordinates for a screen-space mask. Treat an upstream spatial warp as part of sampled geometry or declare that combination unsupported by the fast path until proven. Respect before/after ordering of Glow, color grade, and other FX.

The interactive approximation uses scissored motion bounds for isolated producers and a tile-based, limited-tap gather for more complex scenes. Store coverage, foreground/order or motion identity where obtainable. Include affected pixels outside the original silhouette, and preserve more than one motion candidate near overlaps where the budget permits. A nearby dominant velocity alone tends to smear clean edges and lose thin limbs. With no usable ordering or strongly curved motion, use a small number of actual subframe passes over the affected bounds when affordable. Skip inactive and stationary regions. Accumulate in linear light and premultiplied alpha with normalized exposure weights. Use the renderer’s managed color path and tested half-float render targets where available. Initial proof is SDR including transparent art. Existing HDR export must preserve its current behavior until an HDR-specific path proves color, transfer and bit-depth handling, and the UI must show that limitation rather than silently converting. [Feature-aware motion blur reconstruction](https://research.nvidia.com/publication/2013-11_fast-and-stable-feature-aware-motion-blur-filter)

## Where it fits in the code

Source inspected at `joy-creator` commit `331164acfed017a85594b18ee07974c4c7425cbd`. The existing adjustment FX chain is a good UI and parameter entry point. It has current-frame spatial sampling and a separate Echo Trails history mechanism. Motion Blur needs explicit temporal inputs and producer information, plus a render-order boundary. Reusing previous final output as the blur input would create trails, frame-order dependence and inconsistent scrub/export.

|---|---|
| `AdjustmentLayer`, `FxPanel`, `FxEffectDef`, `FxCompiler` | Reuse effect registration, stack, animation, undo and serialization. Add a capability/pass boundary routed to the temporal renderer. Save stable mode and target IDs, ranges/defaults and versioned parameters. Preserve old projects and unknown settings. |
| `TimeMap` | Reuse clip placement, trim, rate, phase and transition mapping. Expose precise sample-time mapping and discontinuities to both consumers. Distinguish timeline, source and export-chunk time. |
| `FxLivePreviewController`, `FxPreviewTextureView` | Resolve active producers, schedule preview analysis and pass shared shutter/geometry/flow to pooled GLES jobs. Preserve the existing live stack semantics. |
| `ExportManager`, `AdjustmentLayerGlEffect`, `SurfaceFrameReader`, `DecodedFrameCursor` | First prove whether the actual export route exposes the needed scope and neighboring frames, including transition pieces and PiP. Add a bounded queue and a scope render stage or use a targeted offscreen compositor feeding the encoder. Route temporal exports away from incompatible fast paths without changing effects-off behavior. Keep audio timing on the existing export clock. Media3 input/output texture ownership, flush, end of stream and backpressure are part of the adapter. |
| `SpriteFrameResolver`, `PuppetPoseResolver`, `AvatarParamTrack` | Provide resolved cells, pivot/mesh trajectories, discontinuities and renderable pose samples. Keep the contract independent of the Avatar Studio web pilot. |

## Note 9 targets and fallback policy

Targets are proposed release gates. No device numbers are claimed here. Run release/profileable builds on Snapdragon SM-N960U and Exynos SM-N960F, preferably 6 GB units, with their OS and driver versions recorded. Use GLES as the baseline and probe formats and extensions on both. Use a fragment-shader path that works without compute for the core gather. Try GLES 3.1 compute for analysis only if it improves total decode-to-flow performance. Keep resources GPU-resident on the GPU route. Pool texture rings and FBOs, avoid render-thread reads and waits, and reuse only after fences. Prepare shader variants before timed playback. On a hard limit, show sharp unresolved regions or a clear temporary preview status while keeping the edit responsive. At pause or in Inspect Frame, render the chosen completed look. Export retains its quality policy and may run slower. Resize or tile export targets with a halo as large as the capped streak plus reconstruction filter support. Budget intermediate textures before 4K admission. On allocation failure, preserve the chosen quality through a smaller tile if possible, or report the limit.

## Decisions to compare across plans

1. **Use the motion data Studio already owns.** Zooms, curved limb arcs and selected producer scope are required in the proof scene.
2. **Spend export time on actual shutter integration.** Fast estimates give playback room. Per-sample compositing is the quality reference for overlapping art.
3. **Analyze footage asynchronously and make uncertainty visible.** Cold analysis readiness, cached playback and export speed are separate measurements. Weak flow stays sharp locally.
4. **Protect the drawings and their timing.** Default sprite holds, protected parts and intentional cell swaps are part of the animation. Smoothing the drawing transitions is a distinct, opt-in authoring choice.
5. **Make the Note 9 bar falsifiable.** Both chipsets, sustained playback, actual presented frames and bounded analysis/render memory.

Planning status: spec only. The existing roadmap puts motion blur after launch. The Android Avatar Studio redesign is a separate integration dependency. The acceptance targets, defaults and rollout order above are proposed. Phone performance and visual quality remain to be measured.
